    Docker Compose → Podman Quadlet

    Paste a Compose file and get .container, .network and .volume units for systemd, plus install steps. Anything that cannot be carried over exactly is called out.

    Source Compose

    .env variables for interpolation
    Values are substituted into Compose and end up in the export. env_file stays a reference to a file on the host.

    Podman 5.x / 6.x · Linux · systemd · cgroups v2

    Quadlet files

    Quadlet files: 5. Notes: 6. Read README.md before installing.

    [Unit]
Description=ProHomeLab / vaultwarden / db

[Container]
Image=docker.io/library/postgres:17
ContainerName=vaultwarden-db
Network=vaultwarden-default.network
PodmanArgs=--network-alias "db"
Volume=vaultwarden-database-data.volume:/var/lib/postgresql/data
Environment="POSTGRES_DB=vaultwarden"
Environment="POSTGRES_USER=vaultwarden"
Environment="POSTGRES_PASSWORD=replace-with-your-password"
HealthCmd=["/bin/sh","-c","pg_isready -U \"$$POSTGRES_USER\" -d \"$$POSTGRES_DB\""]
HealthInterval=10s
HealthTimeout=5s
HealthStartPeriod=30s
HealthRetries=10
Notify=healthy

[Service]
Restart=always
TimeoutStartSec=900

[Install]
WantedBy=default.target

    Conversion runs in your browser, Compose and .env never leave it. Component licenses

    How to use it

    Paste a docker-compose.yml or open the file. The converter splits it into Quadlet units: a .container per service, .network for networks and .volume for named volumes. A README.md comes with them, with install commands for the mode you pick, rootless or system.

    Give the folder where the Compose file lives on the Linux host: relative bind mounts like ./data and env_file paths are resolved from it. You can paste .env variables separately; they are substituted into the files.

    Everything Quadlet cannot do, or does differently, is listed: what was carried over, what to check and what has to be fixed. One button downloads a ZIP with all the files.

    Questions and answers

    What is Quadlet?

    A systemd generator built into Podman. On systemctl daemon-reload, .container, .network and .volume files become regular systemd services. systemd starts and restarts the containers; there is no daemon as with Docker.

    Where do Quadlet files go?

    For rootless, into ~/.config/containers/systemd/; for system containers, into /etc/containers/systemd/. Subfolders are read too, so the converter puts a project into its own folder. Then run systemctl --user daemon-reload (or sudo systemctl daemon-reload) and start the services.

    How is depends_on converted?

    Into Requires= and After= on the dependent service. With condition: service_healthy in Compose, the dependency gets Notify=healthy: systemd treats it as started only after a passing healthcheck. The converter targets Podman 5 and later.

    Why do rootless containers not start after a reboot?

    The user systemd instance starts only when the user logs in. To bring the services up at boot, enable linger: loginctl enable-linger "$USER". The README includes it when autostart is on.

    What does not carry over?

    Options with no direct Quadlet equivalent, such as build or deploy, are flagged for you to move by hand. restart: unless-stopped becomes Restart=always; the notes explain the difference.

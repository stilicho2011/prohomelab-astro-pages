    OPNsense plan

    To enter by hand in Firewall → Aliases and Firewall → Rules.

    For every rule: Direction In, TCP/IP Version IPv4, Quick on, Source port any. Pass rules use normal state tracking.

    Put the allow rules above the blocks. Move an existing broad Pass below the blocks or replace it. Floating, interface group and automatic rules are evaluated earlier and can change the result.

    The This Firewall block closes DNS, NTP, gateway ping and the OPNsense web UI. Allow whatever the segment needs from the firewall itself with a flow to This Firewall.

    Pass to any lets through all remaining IPv4, including internal routes that are not in the blocks. IPv6, DHCP, NAT and routes are configured separately.

    How to use it

    The planner follows the usual OPNsense segmentation pattern: on every VLAN the specific allow rules come first, then a block to the firewall itself and to all private networks, and last, if needed, internet access. Traffic between segments is closed by default; only the flows you describe are open.

    Enter your segments, tick the ones that need the internet and add flows, for example from LAN to a server in APP on TCP 443, or from IoT to DNS on This Firewall. The plan below updates as you type. Create the aliases in Firewall → Aliases, then the rules on each interface in Firewall → Rules in the same order.

    The address check comes next. If a VLAN subnet matches a Docker or Podman network on some host, that host sends its replies into its own bridge instead of the network. Paste your daemon.json or the subnets from docker network inspect and podman network inspect.

    Questions and answers

    Which VLAN ID should I pick?

    Anything from 2 to 4094. VLAN 1 is the default VLAN on many switches, so keep it out of your own segments. Matching the ID to the third octet helps: VLAN 20 and 192.168.20.0/24 are easy to spot in logs.

    Why does the private network block come before Pass to any?

    OPNsense evaluates interface rules top to bottom and, with Quick on, stops at the first match. If Pass to any sits above the block, traffic to other segments goes through it.

    Why block This Firewall separately?

    This Firewall means every address of OPNsense itself, on every interface. Without the block, any segment can reach the firewall web UI and SSH. That is why DNS to the gateway is allowed with its own flow above the block; without it name resolution in the segment stops.

    Why does Docker break access to a segment?

    Docker takes subnets for its networks from 172.17.0.0/16 and the ranges after it, and from 192.168.0.0/16 once those run out. If one of them matches your VLAN, the host treats those addresses as local and never answers clients in that segment. The fix is default-address-pools.

    Is IPv6 covered?

    No, the plan is IPv4 only. Add IPv6 rules separately; otherwise, with IPv6 enabled, segments can talk to each other around the blocks.

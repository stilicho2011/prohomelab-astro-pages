    Arcane Docker Manager - Setup and Portainer Alternative

    What is Arcane

    Arcane is an open-source (BSD-3-Clause) web UI for Docker, pitched as a modern Portainer alternative. It's still a fairly young project, though it's not brand new either, and it's growing fast - the GitHub repo has already cleared six thousand stars, and the feature list is genuinely impressive: containers, images, volumes, networks, Docker Swarm support, one-click templates, remote environments via agents, image vulnerability scanning, RBAC, and OIDC single sign-on.

    Arcane sits in the gap between Dockge, which is basically married to docker-compose and can't really manage images, networks, or volumes properly (and, let's be honest, the project's more dead than alive at this point), and Portainer, which plenty of people find bloated for a home lab.

    So Arcane is going for a middle ground: a clean, modern UI that still gives you full control over everything Docker can do.

    If you've used Komodo or Portainer before, the philosophical difference with Arcane is that it's first and foremost a UI sitting on top of the Docker Engine on a given host (plus agents for remote hosts), not a full CI/CD platform with procedures and git integration the way Komodo is. For a home lab running one or two hosts, that's arguably simpler and easier to wrap your head around - though to be fair, it does have some CI/CD pipeline capability too.

    It's effectively a competitor to Dockhand, but with one big difference. I mentioned Arcane's license up top for a reason. Dockhand, despite being today's most direct rival, ships under the commercial BSL 1.1 license, and some features sit behind a paywall even in the "free" tier.

    What you'll need before installing

    • A host with Docker and Docker Compose installed.
    • Port 3552 open (the default) or a reverse proxy already configured.
    • A couple of generated secrets - ENCRYPTION_KEY and JWT_SECRET (we'll generate these in step 2).

    Step 1. Write your compose.yaml

    Create a dedicated folder for Arcane and drop a compose.yaml inside it:

    A few things worth flagging right away:

    • PUID/PGID - leave these out and Arcane writes files as its built-in unprivileged user, 65532:65532. If you want files on the host owned by a specific account, set these to that user's UID/GID. They're not just decoration in the compose file.
    • /var/run/docker.sock - a required mount; it's how Arcane actually talks to Docker. I'll cover a safer setup using a socket proxy below.
    • arcane-data - the stock compose file suggests a Docker volume for the database and project data, but I go with a bind mount instead. That's just my own preference.

    You can optionally throw in two more volumes if you plan on using the features they unlock:

    • /builds - the working directory for the Build Workspace (building images straight from a Dockerfile inside the UI).
    • /backups - where Arcane drops exported volume backups. Yes, it can back up your Docker volumes too, so it's worth thinking about which setup fits what you need.

    Step 4. Running SELinux? Read this

    If your hosts are on Fedora/RHEL/CentOS with SELinux turned on, you've got two options:

    Option A - a socket proxy (the one I'd recommend). Instead of mounting docker.sock straight into Arcane, run tecnativa/docker-socket-proxy in front of it. It only exposes the operations you explicitly allow - in the example below that's containers, images, networks, volumes, exec, and events, with no access to secrets, swarm, or system-level operations:

    Honestly, this is worth doing even without SELinux in the picture - it's just good practice, since direct access to docker.sock is basically root on the host. Plenty of people are adopting this pattern now specifically to keep the Docker socket locked down on Debian/Ubuntu boxes too.

    Option B - mount the socket directly, with an SELinux label via security_opt: - label:disable and the :z suffix on the projects volume. Faster to set up, but noticeably looser on security.

    Step 6. Log in for the first time

    Open http://<host-address>:3552 in your browser. On first login, Arcane will make you change the default admin password - do it immediately, before you even think about exposing this to an outside network.

    Step 7. Reverse proxy and WebSocket

    Arcane leans heavily on a WebSocket connection for real-time logs, metrics, and container status, so if you're putting it behind a reverse proxy, you need connection-upgrade proxying enabled. If you're already running Traefik, the labels above cover it.

    Traefik proxies WebSocket out of the box - no extra config needed. Nginx or Apache will need the Upgrade/Connection headers forwarded explicitly, so keep that in mind if you're publishing Arcane through something other than Traefik.

    The image ships with a built-in arcane health command, which slots nicely into a Docker healthcheck:

    start_period buys enough time for the database migrations to finish on first boot, so they don't count against you as failed checks.

    What else Arcane brings to the table

    Beyond the basics of managing containers, images, networks, and volumes, there's a handful of things that make this project worth a proper look, especially if you're eyeing a move off Portainer:

    • Remote Environments - hook up remote Docker hosts through a lightweight agent, similar to Periphery in Komodo, minus the git repo and procedures - it's just another host added to your list of environments.
    • Templates and template registries - deploy common stacks without hand-writing a compose file from scratch.
    • Vulnerability Scans - scan images for known vulnerabilities right from the UI.
    • RBAC and OIDC SSO - already running Authentik or another OIDC provider? Wire Arcane into it for single sign-on, same as you'd do with any other service in your home lab.
    • Docker Swarm - basic support, for the handful of you still running a Swarm cluster.
    • Auto-updates - Arcane can check for and pull its own updates on its own.

    Wrapping up

    Arcane is a solid pick if Portainer feels like overkill and Dockge feels too locked into bare docker-compose without proper image and volume management (not to mention the project's basically stalled). On top of that, you get features Dockhand charges extra for. Getting it running with my compose file takes about 30 seconds - the settings actually worth thinking through ahead of time are generating real secrets, mapping out the path to your existing projects (PROJECTS_DIRECTORY), and, wherever you can, putting a socket proxy between Arcane and the Docker socket instead of mounting it directly.

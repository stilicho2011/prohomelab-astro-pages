    Порты можно перечислить через запятую или задать диапазоном: 443, 8443, 20000-20100. Для ICMP порт не нужен.

    Пересечения с сетями контейнеров

    Для пулов Docker проверяется весь base, size показывает размер выдаваемой подсети.

    Если в Docker задан bip, проверяется его подсеть. Пересечение с пулом - это возможный конфликт: пул выдаст подсеть оттуда, только когда дойдет до нее. Сверяйте с маршрутами хоста.

    В проверенных диапазонах пересечений нет.

    План OPNsense

    Для ручного переноса в Firewall → Aliases и Firewall → Rules.

    Для всех правил: Direction In, TCP/IP Version IPv4, Quick включен, Source port any. Для Pass обычное отслеживание состояния.

    Разрешения ставьте выше блоков. Существующий широкий Pass перенесите ниже блоков или замените. Правила Floating, групп интерфейсов и системные проверяются раньше и могут изменить результат.

    Блок This Firewall закрывает DNS, NTP, ping шлюза и веб-интерфейс OPNsense. Все, что сегменту нужно от самого firewall, разрешите связью «Куда: This Firewall».

    Pass to any пропускает весь оставшийся IPv4, в том числе внутренние маршруты, которых нет в блоках. IPv6, DHCP, NAT и маршруты настраиваются отдельно.

    Как пользоваться

    Планировщик повторяет схему, по которой обычно строят сегментацию в OPNsense: в каждом VLAN сначала точечные разрешения, затем блокировка доступа к самому firewall и ко всем приватным сетям, в конце, если нужно, выход в интернет. Между сегментами по умолчанию все закрыто, открыто только то, что вы описали связью.

    Впишите сегменты, отметьте, каким нужен интернет, и добавьте связи: например, из LAN на сервер в APP по TCP 443 или из IoT к DNS на This Firewall. План ниже пересчитывается сразу. Алиасы создайте в Firewall → Aliases, затем правила на каждом интерфейсе в Firewall → Rules в том же порядке.

    Ниже проверка адресов. Если подсеть VLAN совпадает с сетью Docker или Podman на каком-то хосте, этот хост будет отправлять ответы клиентам в свой bridge, а не в сеть. Вставьте daemon.json или впишите подсети из docker network inspect и podman network inspect.

    Вопросы и ответы

    Какой VLAN ID выбрать?

    Подойдет любой от 2 до 4094. VLAN 1 на многих коммутаторах служебный, его лучше не использовать для своих сегментов. Удобно, когда номер совпадает с третьим октетом: VLAN 20 и 192.168.20.0/24 легко узнать в логах.

    Почему блокировка приватных сетей стоит перед Pass to any?

    OPNsense проверяет правила интерфейса сверху вниз и с включенным Quick останавливается на первом подходящем. Если Pass to any окажется выше блока, трафик в другие сегменты пройдет по нему.

    Зачем отдельно блокировать This Firewall?

    This Firewall - это все адреса самого OPNsense, на всех интерфейсах. Без блока любой сегмент открывает веб-интерфейс и SSH firewall. Поэтому DNS к шлюзу разрешается отдельной связью выше блока, иначе имена в сегменте перестанут разрешаться.

    Почему Docker ломает доступ к сегменту?

    Docker берет подсети для своих сетей из 172.17.0.0/16 и следующих диапазонов, а при их нехватке из 192.168.0.0/16. Если одна из них совпадет с вашим VLAN, хост будет считать эти адреса локальными и не ответит клиентам из сегмента. Лечится настройкой default-address-pools.

    Учитывается ли IPv6?

    Нет, план строится только для IPv4. Правила для IPv6 нужно добавить отдельно, иначе при включенном IPv6 сегменты могут общаться в обход блоков.
